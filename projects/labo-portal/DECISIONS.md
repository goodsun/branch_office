# labo-portal 設計決定記録

*2026-03-07 — マスター（goodsun）× メフィ（CCO）*

---

## 背景

`goodsun/staff_portal` は EC2専用の急造品として生まれた。  
継ぎ足しで機能を追加してきた結果、構造的な問題が蓄積していた。

この日、bon-soleilのポータルを**最初から作り直す**ことを決定した。

---

## 決定事項

### 1. 命名：labo-portal（工房）

**決定**: `staff_portal` を `labo_portal` にリネーム。新実装はこの名称で進める。

**理由**:
- `labo`（laboratoire）＝実験室・工房。bon-soleilの実験精神に合う
- 「工房」という響き——道具を作る場所ではなく、道具を使う人間が自分らしくいられる場所
- 技術用語ではなく人間的な言葉

### 2. 対象：全コンテナ共通の標準ポータル

**決定**: EC2専用ではなく、すべての docker-openclaw コンテナで動く共通ポータルとして設計する。

**理由**:
- どのコンテナ（メフィ・みぃちゃん・テディ・アリス）でも同じ道具棚が必要
- コンテナ固有の機能はプラグインで追加する

### 3. プラグイン3層構造

**決定**:

| 層 | 内容 | 有効化 |
|----|------|--------|
| Layer 1: コア | document_viewer / asset_viewer / services / preset_manager | 自動（設定不要） |
| Layer 2: 標準プラグイン | rag_search / image_gen | `.env` 設定で有効化 |
| Layer 3: 固有プラグイン | mie_chat / file_inbox / cco_dashboard 等 | コンテナごとに自作 |

**理由**:
- RAG・画像生成はほぼ全コンテナが使うが、APIキーが必要なため設定ありで有効化
- 「混ぜるな危険」——層を明確に分けることで、何がどこにあるか常に明確

### 4. 認証：staff_auth依存を断ち切る

**決定**: 認証は自前実装（`core/auth.py`）。`staff_auth` への依存なし。

**理由**:
- staff_authはEC2ホストOS依存（`/Users/teddy/staff-auth`）
- Dockerコンテナ内では動かない
- シンプルなセッション認証（`.env` でパスワード設定）で十分
